fix(query): parens and ANDNOT are group/negation markers, not search terms

Third recurrence of the same root cause found while re-checking the P0-2 fix
with a round-trip property (parse(serialize(x)) == parse(x)) across all 7
sources. Two latent defects of the same family:

1. grouping parens were never stripped. `(meta-analysis OR systematic review)`
   parsed to must=['review)'] / any=[['(meta-analysis', 'systematic']] -- the
   parens became part of the search terms sent upstream, so the API searched
   for a literal "(meta-analysis". Worse, `(rTMS OR "x")` parsed to
   must=[')'], and the serializer then emitted an EMPTY GROUP `()`.

2. ANDNOT (arxiv's exclusion operator) was treated as a plain separator.
   `rTMS ANDNOT 动物` became must=['rTMS','ANDNOT','动物'] -- "exclude animals"
   silently INVERTED into "must contain animals". Semantic inversion is worse
   than a miss: the result is wrong, not merely smaller, and nothing errors.

Also fixed my own guard, which had failed the same way it was meant to prevent:
- it only enumerated literal strings ("AND AND", "OR OR"), so it missed the
  empty group `()` produced by defect 1. Malformed shapes are now enumerated by
  POSITION (leading/trailing operator, operator adjacent to a paren, two
  operators in a row) rather than by specific string.
- its first version also produced a FALSE POSITIVE, rejecting the legitimate
  infix `OR` in `(HAMD OR MADRS)`. Guards are code and can be wrong in both
  directions, so guards now get tests too: malformed input must raise, valid
  input must not.

Tokenizer now splits () and full-width （） into standalone tokens (parens
inside quoted phrases are preserved); the parser treats parens as no-ops while
`andnot` sets pending_not exactly like `NOT` does.

Documented known limitation rather than hiding it: the parser uses a flat model
(must conjunction + any_groups + exclude) and cannot express nested grouping.
`(a OR b c)` degrades to a STRICTER query (an extra required term) rather than
to a malformed one -- deliberately biased toward under-retrieval over sending
garbage upstream. Pinned by test_flat_model_documented_limitation.
