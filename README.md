# MedScholar Agent

> 面向医学研究者的本地化学术智能体。自动检索文献、构建可语义检索的本地知识库、辅助综述与论文写作，并记住你的反馈。

[![CI](https://github.com/arnoldli001/medscholar-agent/actions/workflows/ci.yml/badge.svg)](https://github.com/arnoldli001/medscholar-agent/actions/workflows/ci.yml)

## 一句话定位

**让「AI 辅助写作」在医学场景下可信、可审计、可复现。**

医学写作的失败代价是学术不端。所以重点不在"生成得多漂亮"，而在**幻觉治理**：引用必须对得上、数字必须有出处、错误必须被记住。

## 系统架构

五层，依赖方向单向，由 AST 校验器在 CI 与 pre-commit 里强制执行。

```
┌─────────────────────────────────────────────────────────────────────────┐
│ interface/   入口    server/（FastAPI + uvicorn，57 条 API 路径）         │
│                     cli · mcp                                           │
├─────────────────────────────────────────────────────────────────────────┤
│ application/ 编排    agent/（Orchestrator + Scout/Reader/Critic/Writer）│
│                     Plan→审批→Execute→Reflect→Synthesize，阶段快照可续跑 │
│                     retrieval（混合检索，安全边界在此）                   │
├─────────────────────────────────────────────────────────────────────────┤
│ infrastructure/ 适配 db/（SQLite + FTS5 + sqlite-vec，18 张表）          │
│                     api/（10 个数据源客户端 + 限流/退避）                  │
│                     llm/（client + transport 重试熔断 · JSON 容错）      │
│                     embedding/ · importers/ · export/                    │
├─────────────────────────────────────────────────────────────────────────┤
│ domain/      领域    models · text（CJK 切分）· query · citation        │
│                     dedupe（零 IO）                                     │
├─────────────────────────────────────────────────────────────────────────┤
│ platform/    横切    config · observability · resilience · security      │
│                     cache · prompts（版本化）                             │
│                     —— 只依赖标准库                                       │
└─────────────────────────────────────────────────────────────────────────┘
```

### 分层校验器抓到的真实违规

依赖漂移不体现在业务 diff 里，review 几乎必然漏过。`scripts/check_arch.py`（~470 行，纯 AST、零第三方）已抓到两类问题：

- `importers`（基础设施层）函数体里懒加载 `agent.reader`（应用层）—— 从文件头 import 列表完全看不出来
- `db.repo ↔ embedding.pipeline` 循环依赖 —— 用依赖倒置打断，数据层只留空钩子，嵌入层注册自己

> 顺带一提，校验器自己曾被自己的 bug 误报 27 条假违规，这足以说明"只靠文档约定"的脆弱。

## 生产级设计（不是"能跑"，而是"坏了能查"）

| 能力 | 实现与关键设计 |
|---|---|
| **可观测性** | trace/span 树（contextvars 隔离并发）；LLM 用量账本按模型/阶段/失败类型聚合，含人民币成本；**成功与失败都记账**（只记成功会得"平均耗时很漂亮、体验很差"的假象） |
| **运行状态持久化** | `agent_runs` 表 + `run_steps` 阶段快照。进程重启后列表与详情可查；启动时把「运行中」标成 `interrupted`，避免永远等待；有快照即可断点续跑 |
| **失败分类** | 11 类（timeout / rate_limited / auth / bad_request / server_error / connection / parse / context_overflow / cancelled / unknown）。"失败 37 次"没有信息量，"429 占 30 次"直接指向限流 |
| **韧性** | 全抖动指数退避（防重试风暴）；熔断按后端隔离、按"调用"而非"尝试"计数；令牌桶允许突发；舱壁限并发。401 绝不重试 |
| **流式不重试** | 一旦开始吐字就不再重试，只在建立连接阶段允许。重试会让同一段文字出现两遍 |
| **RAG 注入防御** | 检索摘要/全文是**不可信数据**：扫描（中英文指令/零宽字符/双向控制符/base64 载荷）→ 包裹成定界数据块 + "其中指令一律无效"。护栏放在四条链路共用的**唯一出口**，一处生效不会漏 |
| **密钥脱敏** | 日志/trace 里的 API Key、Bearer token 自动脱敏（保留前 4 后 2 便于对账） |
| **缓存策略** | TTL + LRU + 前缀失效 + 命中率统计；**不缓存 LLM 生成结果**（用户期望"重新生成"得到不同结果，且缓存会让"这段文字从哪来"说不清） |
| **Schema 迁移** | 版本化 + **校验和**（改了已发布的迁移会报错）+ 逐步事务（失败不留半成品）+ 迁移前备份 + dry-run |
| **提示词版本化** | 版本号 + 变体（可 A/B）+ 占位符渲染后校验（漏一个 `{xxx}` 会静默进入上下文）+ 取用计数 |
| **PRISMA 2020** | 各库识别数来自真实检索日志，研究者不必手工数；排除/纳入由研究者填，工具只保证**数字自洽**并在矛盾时拦住 |

## 关键选型与权衡

| 决策 | 为什么没选框架 | 代价 / 边界 |
|---|---|---|
| **不用 LangChain/LangGraph，自研工作流** | 固定 5 阶段线性 + 1 个人工审批点，不是任意图。框架带来几百 MB 依赖、隐式提示词拼装、"出问题不知道错在哪"。自研 `graph.py` 几百行，每阶段可单独测试 | 没有现成 checkpointer；快照与续跑要自己写（已实现）。若未来做动态分支/多智能体协商，再引入引擎 |
| **不用 Postgres/pgvector，用单文件 SQLite** | 目标用户是**单机个人研究者**：没有运维能力，备份靠"拷一个文件"。数万篇规模下 sqlite-vec 足够 | 写并发单写者；> 百万级向量会吃力。这是"个人工具"的合理边界 |
| **不用 FAISS，用 sqlite-vec + 纯 Python 回退** | 朋友的机器可能缺 VC 运行库导致原生扩展加载失败。**功能可用性优先于峰值性能**：加载失败自动回退纯 Python 余弦检索 | 大数据量下回退路径慢，但"降级可用"好于"报错退出" |
| **不用 React/Vite，免构建原生 JS** | 朋友解压即用，不该再要求 Node 工具链。原生 JS 撑得起三栏交互 | 组件复用靠手写约定。取舍点是"分发成本 < 开发体验"选前者 |
| **不用 Celery，用进程内 asyncio + 快照** | 单机单用户场景下引入 broker 只是增加运维负担。真正的需求是"重启不丢进度"，靠快照解决 | 进程崩溃丢失当前阶段的中间结果；不能跨机负载均衡 |
| **引用编号先筛选再重连续分配** | 筛选后编号空洞会导致正文 `[n]` 与参考文献表错位 | 需要额外一轮校验；换来"严格一一对应" |
| **Critic 用「启发式 + LLM」双轨** | 启发式从出版类型/研究设计关键词/样本量/被引/时效性这些**可验证信号**打分，不幻觉、离线可用；LLM 只补充"核心发现/局限" | 启发式对领域细微差异不敏感；融合权重是经验值，未做系统调参（正是评测体系要补的） |
| **数字溯源校验（论文模块）** | 医学论文里编一个 P 值就是学术不端。提示词是概率约束，**程序校验才是确定性约束**：正文每个数字在材料里找出处，找不到列清单 | 会误报（同义表述、换算单位），但对"防编造"误报比漏报可接受 |
| **自研架构校验器** | 依赖漂移不体现在业务 diff 里，review 必然漏过。约 470 行 AST 覆盖三个维度，零第三方依赖 | 需要维护规则与白名单；白名单只允许变小，否则退化成摆设 |

## 深水区：13 个真实踩过的坑

按"现象 → 根因 → 方案 → 验证"记录。

### 1. 中文检索完全失效（FTS5 把整段汉字当成一个 token）

**现象**：库里几百篇中文文献，搜"抑郁"一条都搜不到；英文正常。

**根因**：SQLite FTS5 的 `unicode61` 分词器把连续 CJK 字符视为**单个 token**，`卒中后抑郁`是一个 token，查询 `抑郁` 无法匹配。

**方案**：索引与查询**两侧**都做字符级切分（`segment_cjk` 在汉字间插空格），查询侧用短语（`"抑 郁"`）还原子串语义；叠加三级降级级联（短语 → bigram → bigram-OR），避免长句精确匹配失败就返回空。

**验证**：`test_db.py` 覆盖"中文片段出现在更长短语中"；`test_textutil.py` 锁定 `build_match_query` 的三种模式。

### 2. 78 篇文献嵌入跑 15 分钟没有一条向量（跨事件循环死锁）

**现象**：嵌入管道挂住，CPU 1.3s 几乎为零，日志无报错。

**根因**：缓存的 `httpx.AsyncClient` 连接池**绑定创建它的那个事件循环**。测试与服务先后在不同循环里复用它，请求永久挂起。

**方案**：客户端记录 `_client_loop`，每次请求前校验循环归属，不一致就重建；嵌入提供方改为**每次调用创建短生命周期客户端**。

**验证**：78 篇入库 + 全部生成向量 = **1.6 秒**。

### 3. 「AI 写论文」差点把编造的 P 值写进正文

**现象**：论文初稿出现用户从未提供过的"下降 4.2 分""n=128"。

**根因**：LLM 补全倾向。医学写作的填空式表达（"治疗后 HAMD 下降 __ 分"）会诱使模型生成看起来合理的数字；仅靠系统提示词不可靠。

**方案**：`check_number_provenance()` 用正则抽出正文全部数字，逐个在「用户提供的数据」与「本地文献」里找出处；`12%` 与 `12` 视为等价。找不到的列清单并附上所在句子，返回 `pass/warn/fail`。

**验证**：`test_learning_and_manuscript.py` 用"编造的 4.2 分"与"9999 例"作回归用例。

### 4. 规划阶段偶发崩溃：`'list' object has no attribute 'get'`

**现象**：约 1/3 运行规划阶段报这个错，随后静默降级成模板大纲。

**根因**：**表层**：`extract_json` 在对象解析失败后退回"第一个配平的 `[...]`"，嵌套数组被当成整份答案返回，其他字段全丢。**深层**：模型在检索式内用了未转义双引号，以及 `"query": "("` 后陷入空白循环烧完 token 预算。

**方案**：① `extract_json` 改为**形状感知**——文本以 `{` 开头只认对象，绝不把嵌套数组当答案；② 截断补全（退到最后一个完整值再补括号）；③ `chat_json(expect="object")` 校验顶层类型，不符触发纠错重试；④ 日志补上 `exc_info=True`（原来只有 `%s`，定位不到抛点）。

**验证**：用**真实抓取的两种坏输出**（截断版与畸形版）做回归；修复后生产 Plan 节点实测 `state.errors=[]`、稳定产出 3 条检索式 + 5 章大纲。

### 5. 模型反复重新加载，比生成本身还慢

**现象**：规划"有时 20 秒，有时 6 分钟"。

**根因**：① Ollama 默认 `keep_alive` 5 分钟，超时卸载后重新加载 8B 模型要 60~120 秒；② 更隐蔽：`num_ctx` 是提示词与输出的共享预算，曾经 15,676 字材料占掉 4,129 token，把输出挤到只剩几百字。

**方案**：① 显式设 `keep_alive: 30m` 并记录 `load_duration`，加载超 20 秒告警；② `_fit_digest()` 在预算内**按阶梯收缩材料**（摘要 800→500→400→300→200 字，篇数不限→18→12→8），优先保正文篇幅；③ 补充 `estimate_tokens()` 做预算估算（误差 8%）。

**验证**：规划墙钟从 5~6 分钟降到 **22.6 秒**；`num_ctx` 取 8192/4096/2048 时吞吐为 46.7/46.5/46.9 tok/s（无差异），否掉"减小上下文能提速"的猜想。

### 6. 硬件天花板算清楚了，于是不再瞎调

**现象**：本地 8B 模型慢，怀疑是程序效率问题。

**根因**：`nvidia-smi` 显示 `memory 100%`、SM 频率满血——显存带宽打满。RTX 4060 带宽 272 GB/s ÷ 模型 6.19 GB ≈ **44 tok/s 理论上限**，实测 45~47。

**结论**：生成是带宽受限的串行过程，并发只会排队。转而优化"不产生价值的时间"（模型加载、坏输出重试、串行等待的网络）与"生成多少 token"（字数范围、材料裁剪）。

### 7. 多条检索式串行等待网络（纯浪费）

**现象**：4 条检索式各等 7~10 秒，一轮检索 30 秒以上。

**根因**：单检索式内部的多数据源已经 `asyncio.gather` 并发，但**检索式之间**串行 `await`。

**方案**：检索式之间也并发（信号量限 3），结果**按原顺序整理**，保证日志、统计与界面事件顺序确定。

**验证**：4 条检索式串行 32.7s → 并发约 **10.5s**。

### 8. 前端修了，用户却还在跑旧 JS

**现象**：已修复的 bug，用户复现的还是老错误。

**根因**：① 浏览器缓存了旧 `app.js`；`Cache-Control: no-store` 只能防再次缓存，对已缓存的旧副本无效。② `.bat` 里写 UTF-8 中文被 cmd 的 936 代码页吃字符，LF 换行导致 `goto`/标签失效。

**方案**：① 服务端渲染 `index.html` 时按文件 mtime 给静态资源加 `?v=` 版本号 + `no-store`；② `.bat` 一律改为**纯 ASCII + CRLF**，中文提示移到 Python 侧（用 `WriteConsoleW` 正确输出）。

### 9. XML/HTML 里"看起来对"的字段全错

**现象**：导入 Web of Science 题录后 DOI 全部为空，去重失效、全文获取全失败。

**根因**：**WoS 用 `DI` 表示 DOI，而 RIS 规范是 `DO`**；期刊名用 `SO`（不是 `JO`）、页码用 `BP/EP`（不是 `SP`）。纯文本导出没有短横线，多位作者是缩进续行——按标准 RIS 解析一条都读不出，或把三位作者拼成一个名字。

**方案**：补全标签映射；续行语义按字段区分（可重复字段的续行是新项，单值字段的续行是拼接）；格式识别改为**内容特征优先于扩展名**。

**验证**：`test_importers.py` 用五个数据库的真实导出样式做用例。

### 10. Unpaywall 拒绝占位邮箱

**现象**：按 DOI 查开放获取全文报 HTTP 422。

**根因**：Unpaywall **会校验邮箱真实性**，`example.com` 被明确拒绝。

**方案**：捕获 422 转成可照做的中文提示（去填 `sources.unpaywall.email`），同时告诉用户"也可以直接 `enabled: false` 关掉"——外部依赖不可用时不该变成阻断性故障。

### 11. 守卫脚本在中文 Windows 管道里崩掉

**现象**：`.bat` 校验脚本崩出 `UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'`，崩在"校验通过"那一行。

**根因**：三层叠加。① 脚本打印 `✓`，不在 GBK 里；② 真实控制台不走这个路径（`WriteConsoleW` 绕开了编码），只有**重定向/管道**才按 cp936 编码；③ CI 跑在 UTF-8 Ubuntu 上，永远发现不了。

**方案**：`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`；补上**真实子进程回归测试**：`PYTHONIOENCODING=gbk` 强制非 UTF-8 管道，断言退出码为 0 且 stderr 无 `UnicodeEncodeError`。

**教训**：检查工具本身没有测试，等于把信任建在它身上却没有验过它。

### 12. 材料编号被静默重排

**现象**：写引用忠实度测试时断言"材料里的编号必须与显式编号一致"，直接失败：传入 `[(1, A), (3, B)]` 得到 `[1] A` 与 `[2] B`。

**根因**：`build_context_digest` 的底层 `digest_papers` 只会**从 start_index 顺序递增**，完全忽略调用方传入的 `__index__`。Critic 筛选子集后编号错位。

**影响**：模型说的"第 2 篇"被挂到真编号 2 的那篇上，那篇可能根本不在材料里——点评丢失，或**把差评挂到无关文献头上**。

**方案**：`digest_papers` 在数据带 `__index__` 时使用它，否则退回顺序编号；补上回归测试（传入带空洞的编号）。

**教训**：文档里写下的契约，必须有测试守着——否则它会静静地与实现分叉，代价由下游承担。

### 13. 架构校验器自己的假阳性

**现象**：校验器最初把包的 `__init__.py` 当普通模块解析相对导入，报出 27 条假违规。

**结论**：假阳性会把真问题淹没，所以解析逻辑单独做了核对；它还必须在被测代码有语法错误时**报告而不是崩掉**。

## 性能与质量（实测数据）

> 换机器后用 `scripts/bench_models.py` 与 `scripts/check.py` 可复测。

### 非 LLM 环节：几乎不是瓶颈

| 环节 | 实测结果 |
|---|---|
| 嵌入（`nomic-embed-text`，768 维） | ~60 条/秒 |
| 78 篇文献入库 + 全部生成向量 | **1.6 秒** |
| 跨库检索（4 源并发） | **2~3 秒** |
| 多条检索式并发后的一轮检索 | ~**10.5 秒**（串行为 32.7 秒） |

### LLM 环节：硬件天花板可以算出来

| 场景 | 生成速度 | 规划阶段墙钟 |
|---|---|---|
| 纯 CPU（`qwen3:8b`） | ~7.4 tok/s | 48 秒 |
| **RTX 4060（`qwen3:8b` Q4）** | **45~47 tok/s** | **22.6 秒** |

RTX 4060 显存带宽 272 GB/s ÷ 模型 6.19 GB ≈ **44 tok/s 理论上限**，实测 45~47——说明已是硬件极限。据此断定：并发、调 `num_ctx`（8192/4096/2048 实测 46.7/46.5/46.9 tok/s，无差异）都不会更快。优化预算被投到真正有浪费的地方：

| 浪费点 | 优化 | 收益 |
|---|---|---|
| 模型被卸载后重新加载 | `keep_alive: 30m` | 省掉 60~120 秒/次 |
| 提示词吃掉输出预算 | `_fit_digest()` 阶梯收缩材料 | 正文不再被挤到几百字 |
| 坏输出的重试 | 形状感知解析 + 截断补全 + 纠错重试 | 规划从"偶发崩溃"变为稳定成功 |
| 检索式串行等待 | 检索式之间并发（信号量 3） | 每轮省约 22 秒 |

### 端到端耗时

| 指标 | 实测 |
|---|---|
| 完整「课题 → 综述」（本地 GPU） | ~5~10 分钟 |
| 综述正文篇幅 | 默认目标 4000~8000 字（可配置 800~40000）；单节 1192 字（默认档）/ 2195 字（大字数档） |
| 引用一致性 | 正文 `[n]` 与参考文献表严格一一对应，越界引用被自动剔除 |

### 检索质量

```bat
:: CI 同款：确定性离线回归 + 阈值门禁（秒级，不需要 Ollama）
.python\python.exe scripts\eval_retrieval.py --dataset regression --k 10 --embed-provider hashing --check

:: 本机真实评测：在你自己的库上跑（需要 Ollama）
.python\python.exe scripts\eval_retrieval.py --from-library --limit 60 --k 10 --mode title-terms
```

指标：recall@k / precision@k / MRR / MAP / nDCG@k，配 7 种配置消融矩阵。

**实测（本地库 60 篇，`nomic-embed-text`，title-terms，@10）**：

| 配置 | recall@10 | nDCG@10 | MRR | 相对 BM25 |
|---|---|---|---|---|
| bm25-only | 1.0000 | 0.9754 | 0.9667 | — |
| vector-only | 1.0000 | 0.8967 | 0.8611 | **−7.9pt** |
| production（RRF k=60） | 1.0000 | 0.9815 | 0.9750 | **+0.6pt** |
| weighted-fts2（BM25 ×2） | 1.0000 | 0.9877 | 0.9833 | **+1.2pt** |

**这张表说了三件事，其中两件是对项目自身的批评**：

1. 融合确实优于单路——production 好过 bm25-only 与 vector-only。
2. **向量单路明显弱于 BM25**（nDCG −7.9pt）：语料是英文医学文献、查询由标题派生，词面重叠仍然偏高，语义路拿不到便宜。"上向量检索总是更好"是错的。
3. **recall@10 全部饱和在 1.0，没有区分度**——60 篇语料下 top-10 基本覆盖全部相关文献。小语料上应该看 nDCG/MRR，不要看 recall。

**阴性对照**：一条故意无关的查询（量子色动力学）在语料中确无相关文献，生产配置仍返回 10.0 条（= top_k）。RRF 融合天然总会给出答案，没有"我不知道"的出口——单靠检索层无法拒绝无关问题，必须由下游的引用越界剔除与数字溯源校验兜住。

### 引用支持性校验（claim-level）

```bat
:: 核查库里最新那份综述
.python\python.exe scripts\eval_faithfulness.py --from-db
:: 加上 LLM 逐条判定（跨语言场景建议开）
.python\python.exe scripts\eval_faithfulness.py --from-db --llm
```

**Tier 0（确定性规则，离线、进 CI）**：existence · numbers · direction · overclaim · grounding · cross_lingual。

**Tier 1（`--llm`）**：LLM 逐条判 `supported/partial/unsupported/contradicted` + 理由 + 原文证据；`--self-consistency` 问两次，不一致标 `uncertain`。

**实测（真实综述，21 条带引用论断）**：

```
weakly_supported 21
说明：21 条仅凭语言无关信号（数字/术语/缩写）核对通过，
      0 条因无共同信号而无法核实。语义支持性需 Tier 1。
```

> `weakly_supported` 是实测逼出来的：最初设计成"跨语言一律弃权"，结果同一份综述 **17/21 落进"无法核实"**——中文综述引英文文献本来就是常态，对主要场景全部弃权的校验器等于没有校验器。修法是用语言无关信号恢复判断力。

**校验器自身被衡量过**（人工标注集 27 条）：判定一致 88.9%，预期规则命中 20/20，**二分类 recall = 1.00（零漏报）、precision = 0.89**，`contradicted` 类 P=R=1.00。CI 门禁要求召回必须 1.0。

**已知盲区**：语义改写（同语言上位词替换）会因词面重合过低被误报；跨语言且无任何共同术语时弃权（漏报）。这两条正是需要 Tier 1 / NLI 的原因，并**刻意保留在标注集里持续度量，而不是藏起来**。

## 快速开始

Windows 下双击 **`run.bat`**。自动找 Python、检查依赖、生成配置、启动服务并打开浏览器。

第一次使用建议：
1. 双击 **`run-doctor.bat`** 做环境自检——逐项告知 LLM、嵌入模型、各数据源是否就绪。
2. 确认 Ollama 已启动并拉好模型：
   ```bat
   ollama serve
   ollama pull qwen3:8b
   ollama pull nomic-embed-text
   ```

### 想更快的话

| 方案 | 效果 | 代价 |
|---|---|---|
| 换小模型：`llm.model: qwen3.5:4b` | 约 2 倍 | 质量略降 |
| 调小 `agent.critique_max_papers`（12 → 6） | 评估省一半时间 | 更多文献只能用启发式评分 |
| **改用 DeepSeek 云端 API** | **快一个数量级，质量更好** | 需 Key，按量付费（一次综述不到一毛钱） |

> 不要只看 tok/s 就换小模型：`llama3.2:3b` 快 5 倍，但会把占位符 `[n]` 原样写进正文——看起来有引用，实际对不上参考文献表。综述写作对**引用纪律**的要求比速度更硬。
