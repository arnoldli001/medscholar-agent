# interface-vocabulary-parity

> 这份 skill 来自一个真实缺陷族：AI 在一次生成里同时写下 `parse_query`（解析器）与
> `for_source`（序列化器）。两个函数各自的单元测试都通过，但**序列化器发出的词表
> 严格大于解析器接受的词表**，于是"自己产出的东西自己解析不了"。
> 它在生产里表现为：上游 API 返回 HTTP 200 + 命中 0 条 —— 不报错、不告警、
> 日志记成功，只是搜不到任何东西。
>
> 同一个根因在一个会话里**复发了三次**（`AND`、分组括号、`ANDNOT`），
> 而且**我写的守卫也漏了第四次**（空组 `()`）。所以这份 skill 的重点不是
> "记住这几个词"，而是**把这类缺陷变成可机械检查的性质**。

---

## 0. 先认清这类缺陷的形状

它不是"某一行写错了"，而是**一对函数的契约不闭合**。三个特征：

| 特征 | 说明 |
|---|---|
| **局部正确** | 每个函数单独看都合理，各自的单测都过 |
| **接缝违反性质** | 存在一条跨两个函数的性质被破坏，但没有测试表达它 |
| **失败静默** | 外部系统往往"接受"畸形输入（HTTP 200 / 空结果），错误不回流 |

**最危险的变体是语义反转**：不是"多搜不到"，而是"把排除变成包含"。
本案例里 `-动物`（排除动物）经 `ANDNOT` 往返后变成 `must=['ANDNOT','动物']`
（必须包含动物）——方向完全相反，且没有任何错误信号。

---

## 1. 三种必查性质（按发现能力排序）

### 性质 A：往返一致 `parse(serialize(x)) ≡ x`

**这是发现能力最强的一条。** 只要序列化器与解析器配对存在，就必须有这条测试。

```python
@pytest.mark.parametrize("query", REAL_INPUTS)      # 见 §2：必须是真实输入
@pytest.mark.parametrize("target", ALL_TARGETS)
def test_round_trip(query, target):
    out = serialize(query, target)
    back = parse(out)
    assert semantically_equal(back, parse(query)), (
        f"往返丢失语义：{query!r} -> {out!r} -> {back!r}"
    )
```

不必强求"逐字相等"（大小写、引号风格可以不同），但必须断言**语义等价**：
操作数集合、布尔结构、排除集合三者一致。

**本案例的三次复发全部被这一条覆盖**：
- `AND` 未识别 → `parse(serialize(q))` 多出 `AND` 词
- 分组括号未剥离 → 操作数集合里混进 `(x` / `y)`
- `ANDNOT` 未识别 → 排除集合变空、操作数集合多出 `ANDNOT`

> **落地提示**：如果序列化器是纯函数、解析器是纯函数，这条测试是秒级的，
> 没有任何理由不写。它属于"写一次就能挡住一整族缺陷"的投资。

### 性质 B：守卫的词表必须覆盖**全部**畸形形态

**我在这条上栽过：修 `AND` 时加的输出自检只查了双运算符（`AND AND`），
漏了空组 `()`，于是括号缺陷顺利穿过自检发到上游。**

```python
# 反例：守卫只覆盖刚修的那一个形态
for bad in ("AND AND", "OR OR"):
    assert bad not in expr          # 括号造成的 "()" 完全没被覆盖

# 正例：按"位置"而不是"具体串"来枚举畸形
_OP = r"(?:AND|OR|NOT|ANDNOT)"
BAD_POSITIONS = (
    rf"^\s*\(*\s*{_OP}\b",     # 以连接符开头
    rf"\b{_OP}\s*\)*\s*$",     # 以连接符结尾
    rf"\(\s*{_OP}\b",          # 紧跟左括号
    rf"\b{_OP}\s*\)",          # 紧贴右括号
    rf"\b{_OP}\s+{_OP}\b",     # 两个连接符相连
)
assert not re.search(r"\(\s*\)", expr), "空组"          # 结构退化
assert expr.count("(") == expr.count(")")              # 配平
assert re.search(r"[\w\u4e00-\u9fff]", expr)           # 至少有一个真实操作数
```

**两条纪律**：
1. **按位置枚举，不按具体串枚举**。写 `("AND AND", "OR OR")` 是在赌"只有这一种畸形"；
   写"连接符出现在非中缀位置"才是穷举。
2. **守卫本身要有测试**。守卫是代码，也会写错；给它喂一组畸形输入，
   断言它真的抛错（本案例的守卫第一版有**误报**：把合法的中缀 `OR` 也拦了）。

### 性质 C：测试用例的复杂度 ≥ 真实输入的复杂度

**为什么原测试全绿还是漏了**：旧测试用的查询是

```python
{"query": "rTMS AND depression"}      # 无 OR 组、无括号
```

它**恰好不产生** `AND AND`（`AND` 被当普通词，但只有一个 AND，拼接后是
`(rTMS AND depression AND ...)` 之外的形态没被触发）——不，更准确地说：
这类"裸 AND"输入里，`AND` 被吃进 must 后序列化出来仍然像模像样，
所以测试通过。而生产里 LLM 输出**必然带 OR 组和括号**（同义词、PICO 分层），
于是畸形必然出现。

**纪律**：
- 参数化测试的输入**从生产快照里取**（日志、数据库、真实报文），不要手写。
- 手写输入时问一句："我的输入比真实输入简单吗？" 简化掉的复杂度往往正是 bug 藏身处。
- 现有测试的用例集要定期与真实输入做**形态对比**（有几个操作数、有无分组、有无嵌套）。

## 2. 一份可复制的检查清单

写/审一对相反方向的函数时，逐条过：

- [ ] 列出**序列化器会发出的全部记号**（运算符、分隔符、括号、引号、转义）
- [ ] 列出**解析器会接受的记号**
- [ ] 做差集：`序列化器 - 解析器` 必须为空。**不为空的每一项都是一个潜在缺陷**
- [ ] 反向做差集：`解析器 - 序列化器`（通常是合法的宽松输入，但要有意识）
- [ ] 写往返测试，参数化覆盖**全部目标端**（本例有 7 个数据源，每个的词表都不同）
- [ ] 写输出合法性自检，**按位置**枚举畸形，不按具体串
- [ ] 给自检本身写测试：喂畸形输入断言抛错，喂合法输入断言**不**抛错（防误报）
- [ ] 测试输入取自生产快照，或至少做一次"复杂度对照"
- [ ] 检查失败是否静默：外部系统对畸形输入返回什么？如果是 200/空结果，
      **必须在本地守卫**，不能指望外部报错
- [ ] 检查是否存在**语义反转**路径（排除↔包含、必须↔可选、AND↔OR）

## 3. 为什么 AI 结对编码特别容易出这类缺陷

理解成因才能针对性预防：

| 成因 | 说明 | 对策 |
|---|---|---|
| **一次生成里写完两侧** | 注意力在"每个函数要正确"，不在"两者要闭合" | 生成后**显式做 §2 的差集**，把它当成一步独立动作 |
| **文档先于实现定型** | 本例的 docstring 写"空格/逗号 = AND、`\|` = OR"——**文档词表本身就是解析器词表的子集**，实现忠实于文档，但文档漏了真实输入会带的 `AND` | 文档要写"接受什么"，更要写"**上游实际会发来什么**" |
| **单测按函数组织** | 测试树的结构 = 代码结构，接缝处没有归属 | 为**跨函数性质**单独建测试文件（如 `test_*_contract.py`） |
| **局部测试用例简单** | 手写用例天然比真实输入干净 | 从生产快照取用例 |
| **外部系统静默接受** | 200 + 空结果让缺陷无法自我暴露 | 主动埋“输出形状断言” |

**一句话**：AI 擅长把一个函数写对，不擅长保证**两个函数之间的性质**。
所以人（或下一个 AI）的价值恰好落在接缝上。

## 5. 反模式速查

| 反模式 | 替代 |
|---|---|
| 只测"每个函数各自对不对" | 加一条跨函数性质测试（往返/幂等/不变量） |
| 守卫只查你刚修的那个串 | 按位置枚举全部畸形形态 |
| 守卫没有测试（也就可能有误报/漏报） | 畸形输入断言抛错 + 合法输入断言不抛错 |
| 测试用例手写得很干净 | 从生产快照参数化 |
| 假设"畸形输入会被外部系统拒绝" | 先验证外部行为；若静默，本地必须拦 |
| 文档只写"支持哪些语法" | 同时写"上游实际会发来哪些形态" |
| 把 `ANDNOT` 之类的复合记号当普通分隔符 | 逐个核对它的语义（本例是"排除"，跳过会语义反转） |
